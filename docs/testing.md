# Testing

Read this before writing or fixing tests. `make check` runs everything.

## Backend (`go test ./...`)

- **Services**: table-driven tests with a fake `Repository` in the test file. This is where business rules are
  tested; most tests live here.
- **Handlers**: `httptest.NewRecorder` with a fake `service`, for status codes and the JSON shape.
- **Repositories**: against a real Postgres (`make db-up`), skipped with `t.Skip` when `DATABASE_URL` is unset.
  Never mock SQL.

## Frontend (`npm test`, Vitest + Testing Library)

- Test behaviour through the UI: what the user sees and does (`getByRole`, `userEvent`), not hook internals.
- Mock the network, not hooks: MSW handlers generated by Orval
  (`getCreateReminderMockHandler(data)` from `generated/<tag>/<tag>.msw.ts`), installed with `server.use(...)`.
  For AI providers, add an `http.post('https://api.anthropic.com/v1/messages', …)` handler (see `NoteComposer.test.tsx`).
  Unhandled requests fail the test.
- Wrap renders in a fresh `QueryClient` (`retry: false`) and `NuqsTestingAdapter`.
- Domain functions in `domain/` get plain unit tests.
- Colocate: `NoteComposer.test.tsx` next to `NoteComposer.tsx`.
- Headless Chromium always denies notifications; to check push flows in a real browser, stub
  `Notification.permission` and `PushManager.prototype.subscribe` in an init script.
