# Frontend

React + TypeScript on Vite, CSS Modules, TanStack Query hooks generated by Orval. Read this before editing
anything under `frontend/src/`. Components themselves follow the `react-component` skill.

## Layers (clean architecture)

```
src/
  app/                      router, providers. Assembles features; holds no business logic.
  features/<domain>/
    domain/                 types and pure rules. Imports nothing (no React, no API, no UI).
    api/                    adapters: wrap generated hooks, map DTO → domain, invalidate queries.
    hooks/                  client and URL state, use cases that combine api/ and domain/.
    components/<Name>/      UI. Uses hooks/, api/ and domain/. Never generated code.
    index.ts                public API: the only file other code imports.
  shared/
    ui/<Name>/              design-system components. Know no domain.
    api/http.ts             the only fetch in the app (Orval's mutator).
    api/generated/          Orval output. Never edit, never import outside a feature's api/.
    lib/                    domain-free helpers.
    styles/tokens.css       colors, spacing, type as CSS variables.
```

Dependencies point inward: `components → hooks → api → domain`. `shared/` imports nothing from `features/` or
`app/`. Features never import each other; when two meet, `app/` composes them (slots, `children`).

`.oxlintrc.json` enforces all of this with `no-restricted-imports`, plus a ban on `useEffect` and
`useLayoutEffect`. If lint blocks an import, the design is wrong; don't add an exception.

## The api/ adapter

Components never see transport types. The feature's `api/` maps them once, so a contract change touches one
file. See `src/features/notes/api/remindersApi.ts`: it calls the generated `createReminder()` and returns a
domain `Delivery`, falling back to an in-app reminder when there's no server or push fails.

Our server data is small and write-only (schedule, cancel), so the notes feature calls Orval's plain functions
from `api/` and wraps the use cases in `useMutation` in `hooks/`. When an endpoint returns data to show, use
the generated query hook in `api/`, map DTOs with `select`, and invalidate it from mutations in `onSuccess`.
Expose intent-named functions (`createNote(text)`), not raw `mutate({ data })`.

## Local data

Notes and settings are device-local stores (`shared/lib/createStore.ts`: localStorage + `useSyncExternalStore`,
synced across tabs). The notes store is `features/notes/api/notesStore.ts`; settings are
`shared/lib/settings.ts`. Read them with their hooks, write them through their functions.

## AI and push

- `shared/lib/llm/` turns a zod schema + prompt into typed JSON from the provider in Settings (Anthropic via
  `@anthropic-ai/sdk` with structured outputs; OpenAI, OpenAI-compatible and Gemini via `fetch`). Providers are
  dynamic imports, so they load on first use.
- `shared/lib/push.ts` wraps notifications and the Push API; `shared/lib/permission.ts` exposes permission as a
  store. Permission must be requested from a click (Safari refuses otherwise).
- `features/notes/lib/reminderClock.ts` runs from `main.tsx`: it shows due reminders while the app is open and
  marks them done. Push and in-app notifications for the same reminder share a tag, so the user sees one.

## Voice and the orb

- `shared/lib/orb.ts` is Stack's dithered-sphere drawing code plus `bands`: the rim swells per direction with the
  energy in each frequency band (low voices swell the base, high ones the crown). `npm run icons` draws the app
  icons from it.
- `shared/ui/Orb` runs the canvas loop from a ref callback (no effects) and reads its live props from data
  attributes: `isBusy` spins it, `kick` plays a random reaction, `isListening` reads `readVoice()` every frame.
- `shared/lib/vowel.ts` reads the vowel from the spectrum (F1 = how open, F2 = how front) and maps it to a mouth
  shape: "oo" tall and narrow, "ah" wide open, "ee" flat with a grin. The orb mixes it in by how clearly a vowel
  is heard, and by loudness, so room noise doesn't move it.
- `shared/lib/voice.ts` owns the microphone: an `AnalyserNode` for loudness, pitch and 8 log-spaced bands
  (90 Hz to 4 kHz), and the Web Speech API for the transcript. Start it from a tap; it's a store (`useVoice()`).
  Browsers without speech recognition still get the orb; the user types instead.

## Design language

Follow the Stack app: warm-white paper (`--color-bg`), surfaces lifted by alpha hairline shadows (`--shadow-1`),
never borders; one blue (`--color-accent`, the orb's); Inter with tight tracking for titles; mono for times and
metadata; buttons press to `scale(0.97)` on `--ease-out`; dialogs are bottom sheets on phones.

## State

| State | Home |
|-------|------|
| Server data | Generated query hooks, wrapped in `api/` |
| Filters, tabs, pagination, selected id | URL, with a `nuqs` hook in `hooks/` |
| Forms | `<form action>` + `FormData`, or `useActionState` for pending/errors |
| Shared by one component's pieces | Context in that component's folder |
| Local UI (open, hover) | `useState` where it's used |

## Errors

`http.ts` throws `ApiError` (with `status` and the server's `message`) on any non-2xx. Show query errors where
the data would be; never swallow them.

## Styling

CSS Modules next to each component, values from `shared/styles/tokens.css` only. No hex colors or pixel
spacing outside the tokens file. States through attributes (`data-state`, `aria-pressed`, `:disabled`).
