# Nudge

An installable PWA for quick notes: an AI model (the user's own key) structures each note and turns "remind me…"
into reminders, which a Go server delivers as Web Push notifications at the right time.

How the pieces fit: notes and settings live only in the browser (localStorage). The AI call goes straight from
the browser to the provider. Only reminders (push subscription, title, body, time) go to the server, which sends
them and forgets them. Without a server, reminders ring only while the app is open.

## Stack

- Frontend: React + TypeScript, Vite, CSS Modules, TanStack Query hooks generated by Orval, React Router, nuqs.
  shadcn/ui-style components in `shared/ui` (Radix primitives styled with CSS Modules, no Tailwind), in the
  design language of the Stack app (albsramos/stack-collage): its tokens, hairline shadows, motion and dithered orb.
  PWA via vite-plugin-pwa with our own service worker (`frontend/src/sw.ts`). Hosted on GitHub Pages.
- Backend: Go (`net/http`), Postgres via pgx + sqlc, goose migrations, swag for the OpenAPI spec.
- The API contract is `backend/api/swagger.json`, generated from the handler annotations. Orval reads it.

## Layout

```
frontend/src/app/        router, providers: assembles features
frontend/src/features/   one folder per domain: domain/ api/ hooks/ components/ index.ts
frontend/src/shared/     ui/ (design system, incl. Orb), api/ (http + generated), lib/ (settings, llm/, push, voice, orb), styles/
frontend/src/sw.ts       service worker: precache, push → notification, click → open ?note=<id>
backend/cmd/api/         main.go: wiring only
backend/internal/<domain>/   model, service, repository, handler for one domain
backend/internal/platform/   apperr, httpx, postgres, webpush, db (sqlc output)
backend/db/              migrations/ and queries/
docs/                    area docs, read on demand (see below)
```

## Always

1. Clean architecture: dependencies point inward, never outward.
   Frontend: `components → hooks → api → domain`; only a feature's `api/` imports generated code.
   Backend: `handler → service → repository`; services never import `net/http`, pgx or `db`.
2. Never edit generated code (`frontend/src/shared/api/generated/`, `backend/api/`, `backend/internal/platform/db/`). Run `make gen`.
3. Never hand-write an API type or a `fetch` call to our API. Use the generated code through the feature's `api/`.
   The one exception: AI providers, called only from `frontend/src/shared/lib/llm/` (Anthropic through its SDK).
4. No `useEffect`. Server data comes from query hooks, shareable UI state from the URL, the rest is derived.
5. Build every React component with the `react-component` skill.
6. Boolean props and fields start with `is` or `are`.
7. Never send notes or keys to our server. It receives reminders only; the API key stays on the device.
8. Times are UTC on the wire, RFC 3339 strings.

## Read before you…

- add or change a React component → use the `react-component` skill
- add a frontend feature → use the `add-feature` skill
- edit anything under `frontend/src/` → `docs/frontend.md`
- add or change an endpoint → use the `add-endpoint` skill
- edit Go code under `backend/` → `docs/backend.md`
- change the schema or a SQL query → use the `db-migration` skill (details: `docs/database.md`)
- touch swagger annotations, `orval.config.ts` or generated clients → `docs/api-contract.md`
- write or fix tests → `docs/testing.md`
- deploy, or touch the PWA, service worker or push → `docs/deploy.md`
